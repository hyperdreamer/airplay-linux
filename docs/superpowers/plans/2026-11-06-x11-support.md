# KDE Plasma 6 X11 Mirror Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use the deterministic
> subagent-driven-development controller to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax; leave them unticked during execution.

**Goal:** Enable portal-backed Mirror on KDE Plasma 6 X11 while keeping Virtual display Wayland-only, preserving existing evidence requirements, and reporting session and mode availability in human-readable form.

**Architecture:** Keep session profile tokens as the policy identity and centralize their display labels in `environment_label`. `EnvironmentProbe` will gate Mirror and Virtual display independently and attach a closed, precedence-ordered refusal reason; the UI will project that reason through a fixed sentence table and render it below the mode selector. A separately guarded, read-only live X11 test module and one operations paragraph complete the documentation lane; no capture, portal, inventory, or display-creation implementation is changed.

**Tech Stack:** Python 3.12+, `StrEnum`, pytest/pytest-asyncio/pytest-qt, PySide6, the existing portal and KScreen adapters.

**Authority:** Implement approved specification `docs/superpowers/specs/2026-11-06-x11-support-spec.md` (SHA-256 `9b01f363edc444fd4655b30421161b5bd66df8cce8648dbeda208761505df24a`) and design revision 4 only. The specification's exact tables, test names, and acceptance procedure are normative.

**Coverage:** Specification §§2-5 and 9 policy/domain/export requirements are Tasks 1-2; §§6 and 9 UI projection/rendering requirements are Tasks 3-4; §§9-10 documentation and read-only live checks are Task 5.

**Verification and acceptance:** the full suite and the guarded live-module skips are run by the Project Manager after the last lane integrates, not by a lane. The seven-step live run in the specification's section 11 is performed by the operator with the Project Manager, because it needs a person to accept the desktop ScreenCast prompt and watch the receiver.
